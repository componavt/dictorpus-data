# Набор данных для морфологического снятия омонимии ВепКар

Этот каталог содержит исходные данные, экспортированные из корпуса **ВепКар** для проекта **контекстного ранжирования морфологических разборов в ВепКар**.

Проект изучает **ранжирование кандидатов морфологического разбора**:

```text
слово в предложении
        +
его кандидаты морфологического разбора
        ↓
ранжировать / выбрать корректный анализ wordform + gramset
```

Набор данных **не** предназначен для снятия лексической омонимии, выбора леммы или семантической аннотации. Основная идентичность кандидата — пара:

```text
wordform_id + gramset
```

Числовой `gramset_id` связывает кандидата со справочником [`../dict/grammar/gramsets.csv`](../dict/grammar/README.ru.md) и со словарной морфологией [`../dict/morphology/`](../dict/morphology/README.ru.md).

Значения `corpus_id`, `genre_id` и `dialect_code` в метаданных текстов расшифровываются справочниками [`reference/`](reference/README.ru.md): `corpora.csv`, `genres.csv`, `dialects.csv`.

## Формат хранения

Полные исходные данные ВепКар хранятся как отдельные UTF-8 CSV-файлы, сжатые Zstandard:

```text
*.csv.zst
```

Каждый CSV сжат отдельно с уровнем Zstandard `-19`.

Например:

```text
candidate_analyses_lud.csv.zst
sentences_vep.csv.zst
texts_krl.csv.zst
words_olo.csv.zst
```

Коды языковых разновидностей в именах файлов:

| Код | Языковая разновидность |
|---|---|
| `vep` | Вепсский язык |
| `krl` | Собственно карельское наречие карельского языка |
| `olo` | Ливвиковское наречие карельского языка |
| `lud` | Людиковское наречие карельского языка |

В [`samples/`](samples/) находятся небольшие несжатые примеры. Они предназначены для просмотра на GitHub, документации, быстрого ознакомления и локальной отладки. Это **не** benchmark-подмножество и не материал для исследовательской оценки.

## Обзор файлов

Для каждой языковой разновидности есть четыре типа файлов:

```text
candidate_analyses_<lang>.csv.zst
sentences_<lang>.csv.zst
texts_<lang>.csv.zst
words_<lang>.csv.zst
```

Связи между ними:

```text
texts
  └── sentences
        └── words
              └── candidate analyses
```

```text
texts_<lang>.csv
    text_id
       │
       ▼
sentences_<lang>.csv
    sentence_id, text_id
       │
       ▼
words_<lang>.csv
    word_id, sentence_id, word_number, word, w_id, s_id
       │
       ▼
candidate_analyses_<lang>.csv
    word_id, wordform_id, gramset_id, gramset, relevance
```

## `candidate_analyses_*.csv`

Это центральный файл для ранжирования кандидатов. Одна строка представляет один возможный морфологический анализ, связанный со словом корпуса.

Пример:

```csv
word_id,wordform_id,gramset_id,gramset,relevance
3675349,8063,1,SG+NOM,1
3675349,8063,56,SG+ACC,1
3675350,2111182,8,SG+IN,2
```

| Поле | Тип | Описание |
|---|---|---|
| `word_id` | integer | Идентификатор слова корпуса. Соответствует `words.id` и связывает таблицу с `words_*.csv`. |
| `wordform_id` | integer | Идентификатор кандидата словоформы словаря. Соответствует `text_wordform.wordform_id`. |
| `gramset_id` | integer | Идентификатор грамматического набора. Присоединяется к `../dict/grammar/gramsets.csv`; см. [ниже](#кандидаты-без-грамматического-набора) об особых значениях. |
| `gramset` | string or empty | Компактное представление грамматического набора признаков. Строится только из кодов `lgr` граммем и совпадает с `gramsets.csv` для того же `gramset_id`. Примеры: `SG+NOM`, `SG+IPFV.PST+1+IND+POS`, `INF`, `ACT+IPFV.PTCP`. |
| `relevance` | integer | Статус морфологического кандидата в ВепКар: `0` — отклонённый кандидат; `1` — автоматически предложенный, но не выбранный экспертом кандидат; `2` — кандидат, выбранный экспертом как корректный. |

### Важное правило: gold-кандидат

Для задачи морфологического снятия омонимии кандидат считается выбранным экспертом только при:

```text
relevance = 2
```

Не используйте условие `relevance > 1` как универсальное правило для других данных ВепКар. Значения выше единицы в наборах семантического выбора примеров имеют иной смысл; здесь целевой морфологический статус определён именно так.

### Группы кандидатов

Все строки с одинаковым `word_id` образуют набор кандидатов для одного слова корпуса:

```text
word_id = 3675349

кандидат 1: wordform_id = 8063, gramset_id = 1,  gramset = SG+NOM
кандидат 2: wordform_id = 8063, gramset_id = 56, gramset = SG+ACC
```

Производные поля — число кандидатов, статус омонимии, gold label, train/dev/test split и флаги качества — намеренно не хранятся в исходном экспорте. Их следует получать воспроизводимыми скриптами подготовки в отдельном каталоге результатов.

### Кандидаты без грамматического набора

В 13 853 строках `gramset` пуст, и у всех них `gramset_id = 0` (88 в `vep`, 487 в `krl`, 13 099 в `olo`, 179 в `lud`). Значения `0` нет в `gramsets.csv`, поэтому внутреннее соединение со справочником такие строки потеряет. Среди них есть и строки с `relevance = 2`.

Тройка `word_id + wordform_id + gramset_id` уникальна во всех файлах.

## `sentences_*.csv`

Одна строка представляет одно предложение ВепКар.

Пример:

```csv
sentence_id,text_id,sentence_xml,sentence_ru
41509,1566,"<s id=""1""><w id=""1"">Kouz</w> ... </s>","Когда я жила в Пелдоже ..."
```

| Поле | Тип | Описание |
|---|---|---|
| `sentence_id` | integer | Идентификатор предложения; связывает таблицу с `words_*.csv`. |
| `text_id` | integer | Идентификатор текста ВепКар; связывает таблицу с `texts_*.csv`. |
| `sentence_xml` | string | Исходное предложение в XML-разметке ВепКар. Элементы слов имеют вид `<w id="...">...</w>`; пунктуация сохраняется в XML-тексте предложения. |
| `sentence_ru` | string or empty | Русский перевод предложения, когда он есть. Пустое значение означает отсутствие выровненного русского перевода. |

### Контекст предложения

Основной контекст проекта — одно предложение. Последовательность слов восстанавливается выборкой всех строк `words_*.csv` с одинаковым `sentence_id` и сортировкой по `word_number`.

`sentence_xml` сохраняет исходное оформление предложения, пунктуацию и графическую форму слов. `words.word`, напротив, содержит нормализованную форму, используемую ВепКар для поиска и морфологической обработки.

## `texts_*.csv`

Одна строка описывает метаданные текста ВепКар.

Пример:

```csv
text_id,corpus_id,dialect_code,genre_id,year_recorded,year_published
1566,1,lud-svt,11,1969,1978
1601,3,,,2018,
2042,1|4,krl-tlm,12,1960,2016
```

| Поле | Тип | Описание |
|---|---|---|
| `text_id` | integer | Идентификатор текста ВепКар; связывает таблицу с `sentences_*.csv`. |
| `corpus_id` | string or empty | Один или несколько идентификаторов из [`reference/corpora.csv`](reference/README.ru.md#corporacsv), разделённых `\|`. Пустое значение означает отсутствие подкорпуса в экспорте. |
| `dialect_code` | string or empty | Один или несколько кодов из [`reference/dialects.csv`](reference/README.ru.md#dialectscsv), разделённых `\|`. Пустое значение означает отсутствие кода в экспорте. |
| `genre_id` | string or empty | Один или несколько идентификаторов из [`reference/genres.csv`](reference/README.ru.md#genrescsv), разделённых `\|`. Пустое значение означает отсутствие жанровой аннотации в экспорте. |
| `year_recorded` | integer or empty | Год записи исходного материала; источник — `events.date`. |
| `year_published` | integer or empty | Год публикации, указанный в связанном источнике; источник — `sources.year`. |

`year_recorded` и `year_published` — независимые поля: отсутствующее значение одного не заполняется значением другого. Оба выгружаются как есть, без приведения типа; в текущей выгрузке все непустые значения — четырёхзначные годы. Пустая ячейка означает отсутствие значения; маркер `\N` в этих полях не используется.

Правила соединения многозначных полей со справочниками описаны в [README справочников](reference/README.ru.md#соединение-с-метаданными-текстов).

Метаданные текста могут использоваться как дополнительные признаки в экспериментах: например, для проверки, улучшают ли ранжирование кандидатов диалект, жанр, принадлежность к подкорпусу или год записи.

## `words_*.csv`

Одна строка представляет слово, выделенное ВепКар в корпусном предложении.

Пример:

```csv
word_id,sentence_id,word_number,word,w_id,s_id
3675348,41509,1,kouz,1,1
3675349,41509,2,minä,2,1
3675350,41509,3,pеlduoižis,3,1
3675351,41509,4,elin,4,1
```

| Поле | Тип | Описание |
|---|---|---|
| `word_id` | integer | Идентификатор слова корпуса. Соответствует `words.id` и связывает слово с `candidate_analyses_*.csv`. |
| `sentence_id` | integer | Идентификатор содержащего предложения. Связывает слово с `sentences_*.csv`. |
| `word_number` | integer | Позиция слова в предложении. Сортируйте по этому полю, чтобы восстановить нормализованную последовательность слов. |
| `word` | string | Нормализованная словоформа ВепКар для поиска и морфологического сопоставления. Нормализация включает нижний регистр, удаление апострофоподобных знаков смягчения и контекстно-зависимую нормализацию `w` по гармонии гласных. |
| `w_id` | integer | Идентификатор элемента `<w id="…">` в XML текста; источник — `words.w_id`. |
| `s_id` | integer | Идентификатор элемента `<s id="…">` в XML текста; источник — `words.s_id`. |

### Нормализация слов

Поле `word` намеренно не всегда совпадает с графической формой внутри `sentence_xml`:

```text
sentence_xml
    → исходное представление предложения, пунктуация, исходное написание

words.word
    → нормализованная форма для поиска в корпусе и морфологии
```

Нормализованное `word` — основной вход для морфологических моделей в этом проекте. Исходную поверхностную форму при необходимости можно восстановить из `sentence_xml` по `w_id` (см. ниже).

### Связь с исходной XML-разметкой

```text
word_id      -> words.id          запись БД
sentence_id  -> sentences.id      запись БД

w_id         -> <w id="...">      элемент XML текста
s_id         -> <s id="...">      элемент XML текста
```

`w_id` и `s_id` нумеруют элементы внутри XML одного текста, поэтому они не уникальны глобально. `word_number` задаёт позицию слова в предложении и не заменяет `w_id`.

Чтобы получить исходное написание слова:

1. Найдите предложение по `sentence_id` в `sentences_*.csv`.
2. Убедитесь, что атрибут `<s id="…">` в `sentence_xml` равен `s_id`.
3. Найдите внутри предложения элемент `<w>` с `id`, равным `w_id`.
4. Извлеките текст элемента XML-парсером.

Не ищите слово в XML по нормализованному `word`: написание может отличаться, а одинаковые слова могут повторяться в предложении.

`w_id` и `s_id` выгружаются из БД без пересчёта. В текущей выгрузке оба поля заполнены во всех строках. Для слов, предложение которых есть в `sentences_*.csv`, соответствие не найдено в немногих случаях: в `vep` у 124 слов нет `<w>` с таким `w_id`, в `olo` у 4 слов `s_id` не совпадает с `<s id>` и у 6 слов не найден `w_id`. Такие слова не удаляются из выгрузки.

### Слова без предложения

Часть строк ссылается на `sentence_id`, которого нет в `sentences_*.csv`: 1 648 в `krl`, 449 в `olo` и 173 в `vep`. При внутреннем соединении эти слова будут потеряны.

## Правила CSV

Все файлы используют:

```text
Кодировка:             UTF-8
Разделитель:           запятая (,)
Символ кавычек:        двойная кавычка (")
Экранирование кавычек: двойная двойная кавычка ("")
```

Значение заключается в кавычки, только если этого требует его содержимое: например, при запятой или кавычке внутри текста. Поэтому читайте файлы CSV-парсером, а не разбором строк.
