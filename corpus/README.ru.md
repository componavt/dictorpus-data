# Набор данных для морфологического снятия омонимии ВепКар

Этот каталог содержит исходные данные, экспортированные из корпуса **ВепКар** для проекта **контекстного ранжирования морфологических разборов в ВепКар**.

Проект изучает **ранжирование кандидатов морфологического разбора**:

```text
слово в предложении
        +
его кандидаты морфологического разбора
        ↓
ранжировать / выбрать корректный анализ wordform + gramset
```

Набор данных **не** предназначен для снятия лексической омонимии, выбора леммы или семантической аннотации. Основная идентичность кандидата — пара:

```text
wordform_id + gramset
```

## Формат хранения

Полные исходные данные ВепКар хранятся как отдельные UTF-8 CSV-файлы, сжатые Zstandard:

```text
*.csv.zst
```

Каждый CSV сжат отдельно с уровнем Zstandard `-19`.

Например:

```text
candidate_analyses_lud.csv.zst
sentences_vep.csv.zst
texts_krl.csv.zst
words_olo.csv.zst
```

Коды языковых разновидностей в именах файлов:

| Код | Языковая разновидность |
|---|---|
| `vep` | Вепсский язык |
| `krl` | Собственно карельский язык |
| `olo` | Олонецкий карельский язык |
| `lud` | Людиковское наречие карельского языка |

В [`samples/`](samples/) находятся небольшие несжатые примеры. Они предназначены для просмотра на GitHub, документации, быстрого ознакомления и локальной отладки. Это **не** benchmark-подмножество и не материал для исследовательской оценки.

## Обзор файлов

Для каждой языковой разновидности есть четыре типа файлов:

```text
candidate_analyses_<lang>.csv.zst
sentences_<lang>.csv.zst
texts_<lang>.csv.zst
words_<lang>.csv.zst
```

Связи между ними:

```text
texts
  └── sentences
        └── words
              └── candidate analyses
```

```text
texts_<lang>.csv
    text_id
       │
       ▼
sentences_<lang>.csv
    sentence_id, text_id
       │
       ▼
words_<lang>.csv
    word_id, sentence_id, word_number, word
       │
       ▼
candidate_analyses_<lang>.csv
    word_id, wordform_id, gramset, relevance
```

## `candidate_analyses_*.csv`

Это центральный файл для ранжирования кандидатов. Одна строка представляет один возможный морфологический анализ, связанный со словом корпуса.

Пример:

```csv
word_id,wordform_id,gramset,relevance
3675349,8063,SG+NOM,1
3675349,8063,SG+ACC,1
3675350,2111182,SG+IN,1
```

| Поле | Тип | Описание |
|---|---|---|
| `word_id` | integer | Идентификатор слова корпуса. Соответствует `words.id` и связывает таблицу с `words_*.csv`. |
| `wordform_id` | integer | Идентификатор кандидата словоформы словаря. Соответствует `text_wordform.wordform_id`. |
| `gramset` | string | Компактное представление грамматического набора признаков. Строится из атрибутов ВепКар, используя коды `lgr` и при необходимости `name_short_en`. Примеры: `SG+NOM`, `SG+IPFV.PST+1+IND+POS`, `INF`, `ACT+IPFV.PTCP`. |
| `relevance` | integer | Статус морфологического кандидата в ВепКар: `0` — отклонённый кандидат; `1` — автоматически предложенный, но не выбранный экспертом кандидат; `2` — кандидат, выбранный экспертом как корректный. |

### Важное правило: gold-кандидат

Для задачи морфологического снятия омонимии кандидат считается выбранным экспертом только при:

```text
relevance = 2
```

Не используйте условие `relevance > 1` как универсальное правило для других данных ВепКар. Значения выше единицы в наборах семантического выбора примеров имеют иной смысл; здесь целевой морфологический статус определён именно так.

### Группы кандидатов

Все строки с одинаковым `word_id` образуют набор кандидатов для одного слова корпуса:

```text
word_id = 3675349

кандидат 1: wordform_id = 8063, gramset = SG+NOM
кандидат 2: wordform_id = 8063, gramset = SG+ACC
```

Производные поля — число кандидатов, статус омонимии, gold label, train/dev/test split и флаги качества — намеренно не хранятся в исходном экспорте. Их следует получать воспроизводимыми скриптами подготовки в отдельном каталоге результатов.

## `sentences_*.csv`

Одна строка представляет одно предложение ВепКар.

Пример:

```csv
sentence_id,text_id,sentence_xml,sentence_ru
41509,1566,"<s id=""1""><w id=""1"">Kouz</w> ... </s>","Когда я жила в Пелдоже ..."
```

| Поле | Тип | Описание |
|---|---|---|
| `sentence_id` | integer | Идентификатор предложения; связывает таблицу с `words_*.csv`. |
| `text_id` | integer | Идентификатор текста ВепКар; связывает таблицу с `texts_*.csv`. |
| `sentence_xml` | string | Исходное предложение в XML-разметке ВепКар. Элементы слов имеют вид `<w id="...">...</w>`; пунктуация сохраняется в XML-тексте предложения. |
| `sentence_ru` | string or empty | Русский перевод предложения, когда он есть. Пустое значение означает отсутствие выровненного русского перевода. |

### Контекст предложения

Основной контекст проекта — одно предложение. Последовательность слов восстанавливается выборкой всех строк `words_*.csv` с одинаковым `sentence_id` и сортировкой по `word_number`.

`sentence_xml` сохраняет исходное оформление предложения, пунктуацию и графическую форму слов. `words.word`, напротив, содержит нормализованную форму, используемую ВепКар для поиска и морфологической обработки.

## `texts_*.csv`

Одна строка описывает метаданные текста ВепКар.

Пример:

```csv
text_id,corpus_id,dialect_code,genre_id,year_recorded
1566,1,lud-svt,11,1969
1601,3,,,2018
```

| Поле | Тип | Описание |
|---|---|---|
| `text_id` | integer | Идентификатор текста ВепКар; связывает таблицу с `sentences_*.csv`. |
| `corpus_id` | integer | Идентификатор корпуса или подкорпуса, к которому относится текст. |
| `dialect_code` | string or empty | Код диалекта ВепКар. Несколько кодов разделяются `|`; пустое значение означает отсутствие кода в экспорте. |
| `genre_id` | integer or empty | Идентификатор жанра. Несколько идентификаторов разделяются `|`; пустое значение означает отсутствие жанровой аннотации в экспорте. |
| `year_recorded` | integer or empty | Год записи исходного материала, если он известен. |

Метаданные текста могут использоваться как дополнительные признаки в экспериментах: например, для проверки, улучшают ли ранжирование кандидатов диалект, жанр, принадлежность к подкорпусу или год записи.

## `words_*.csv`

Одна строка представляет слово, выделенное ВепКар в корпусном предложении.

Пример:

```csv
word_id,sentence_id,word_number,word
3675348,41509,1,kouz
3675349,41509,2,minä
3675350,41509,3,pеlduoižis
3675351,41509,4,elin
```

| Поле | Тип | Описание |
|---|---|---|
| `word_id` | integer | Идентификатор слова корпуса. Соответствует `words.id` и связывает слово с `candidate_analyses_*.csv`. |
| `sentence_id` | integer | Идентификатор содержащего предложения. Связывает слово с `sentences_*.csv`. |
| `word_number` | integer | Позиция слова в предложении. Сортируйте по этому полю, чтобы восстановить нормализованную последовательность слов. |
| `word` | string | Нормализованная словоформа ВепКар для поиска и морфологического сопоставления. Нормализация включает нижний регистр, удаление апострофоподобных знаков смягчения и контекстно-зависимую нормализацию `w` по гармонии гласных. |

### Нормализация слов

Поле `word` намеренно не всегда совпадает с графической формой внутри `sentence_xml`:

```text
sentence_xml
    → исходное представление предложения, пунктуация, исходное написание

words.word
    → нормализованная форма для поиска в корпусе и морфологии
```

Нормализованное `word` — основной вход для морфологических моделей в этом проекте. Исходную поверхностную форму при необходимости можно восстановить из `sentence_xml`.

## Правила CSV

Все файлы используют:

```text
Кодировка:             UTF-8
Разделитель:           запятая (,)
Символ кавычек:        двойная кавычка (")
Экранирование кавычек: двойная двойная кавычка ("")
```

Текстовые поля, включая XML-предложения и русские переводы, заключаются в кавычки. Поэтому запятые, кавычки и пунктуация внутри текста не меняют структуру CSV.

## Политика исходных данных

Файлы этого каталога — исходные экспорты и должны считаться доступными только для чтения:

```text
corpus/
    неизменяемый экспорт исходных данных ВепКар

results/
    производные instances, labels, train/dev/test splits,
    признаки, predictions, models, diagnostics и reports
```

Не перезаписывайте, не редактируйте и не дописывайте результаты экспериментов в исходные файлы. Исходный экспорт не виноват в ваших экспериментах. 🙂
